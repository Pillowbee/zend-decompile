# Zend Decompiler v29

Экспериментальный **офлайн-инструмент** для исследования ограниченного набора сериализованных Zend Encoder / PHP 5.2-файлов. Восстановленный PHP — **непроверенный кандидат**, а не гарантированно эквивалентный исходник. Синтаксическая проверка `php -n -l` сама по себе не доказывает эквивалентность.

## Структура проекта

```text

  __main__.py               python -m zend_decompiler

  prefix_restore.py         инструкции, выражения и временные значения
  encoder_calls.py          вызовы Encoder по таблице символов файла
  cfg.py, crossblock.py     граф управления и межблочные связи
  structure.py, state.py    структурирование и консервативная эмиссия
  batch.py                  пакетная обработка
  assets.py, calibrate.py   источники данных и карта opcode
  *_audit.py, triage.py,
  readonly_dataflow.py,
```

Корень проекта содержит конфигурацию, документацию и тестовые артефакты, но **не содержит рабочих Python-скриптов**. Внутренние импорты пакета относительные; старые имена верхнеуровневых модулей `zend_*.py` удалены. Исходники доступны в `src/zend_decompiler/`.

## Установка и тестирование

Python **3.10+**, `networkx>=2.8`.

```bash
python -m pip install -r requirements.txt
export PYTHONPATH=src
python -m unittest discover -s tests -v
python -m zend_decompiler validate
python -m zend_decompiler --version
```

Для запуска достаточно исходного каталога и зависимости `networkx`; установка самого проекта не требуется. Команда `validate` работает только при наличии `tests/` и `golden/reference/` и сообщает об ошибке, если этих данных нет.

## Использование

Команды запускаются из корня checkout, с выводом **за пределами** `sample_inputs/`:

```bash
python -m zend_decompiler batch sample_inputs -o /tmp/zend_batch --isolate-parser
python -m zend_decompiler restore sample_inputs/basket.php \
  -o /tmp/basket_candidate.php --audit /tmp/basket_audit.json --isolate-parser
python -m zend_decompiler audit sample_inputs/basket.php
python -m zend_decompiler dataflow sample_inputs/fun_all.php -o /tmp/fun_all_dataflow.json
python -m zend_decompiler.triage sample_inputs/fun_all.php 'sample_inputs/links_fun(1).php' -o /tmp/triage.json
python -m zend_decompiler.ir_evidence sample_inputs/fun_all.php -o /tmp/ir_evidence.json
# Независимая экспериментальная диагностика (не генерирует PHP):
python -m zend_decompiler.header_call_hypothesis 'sample_inputs/links_fun(1).php' \
  sample_inputs/fun_all.php -o /tmp/header_calls_experimental.json
```

`--isolate-parser` — ограниченная Linux-изоляция парсера, не общая песочница. `batch` возвращает код **2**, если встречается `unsupported`; это ожидаемо для текущего набора. Проверенный результат: **11 входов → 10 candidate_generated, 0 unsupported, 1 not_encoded** — единственный незакодированный вход отвергается по формату, готовый PHP для него не создаётся.

## Критерии успешности

Прогресс оценивается **только двумя показателями**:

1. **Количество успешно пройденных тестов** (`unittest`; пропуски не засчитываются).
2. **Количество полностью обработанных закодированных PHP-файлов** со статусом `candidate_generated`. Частичные фрагменты, `unsupported` и `not_encoded` не засчитываются.

Последний полный локальный прогон тестов после поддержки конструкции `foreach`: **181 успешный тест из 184 (3 пропущены)**. Последний устойчивый batch baseline: **10 файлов-кандидатов из 11 входов**. `batch` выводит актуальные счётчики после каждого запуска; код завершения 2 при наличии `unsupported` ожидаем. PHP-кандидаты не гарантируют точного восстановления исходника.

**Обратная совместимость со старыми API, выходными форматами и поведением прежних выпусков не требуется.** Старые эталоны можно пересматривать при развитии алгоритма. Увеличение числа выполненных тестов за счёт их искусственного упрощения не считается прогрессом.

## Текущая разработка вызовов и автоматические проверки

- В `prefix_restore.py` добавлена ограниченная поддержка прямых именованных вызовов PHP 5.2 вида `SEND_* → DO_FCALL` без `INIT_FCALL_BY_NAME`: строго упорядоченные аргументы, известное имя функции, проверенное количество аргументов, завершение внутри одного базового блока. Правила не интерпретируют спорный opcode `140` и не разрешают неизвестные межблочные состояния.
- Новые `tests/test_call_protocol.py` и `tests/test_direct_calls.py` проверяют как успешные последовательности, так и отказ при нарушении протокола. К исходным 82 тестовым методам добавлено 22 содержательных теста прямых вызовов и арифметики; все 104 метода проверены в чистом checkout (101 успешный, 3 пропуска).
- `header_call_hypothesis.py` — **экспериментальная read-only диагностика** предполагаемых вызовов через `header_symbols`. Проверяет сигнатуры, аргументы и границы CFG, но не меняет opcode-map, `restore_core` или статусы `candidate_generated`. В текущем наборе 15/18 структурных соответствий проходят ограниченные проверки, 3/18 не проверяются из-за неполного CFG. Дополнительные 23 Python-теста не означают восстановления новых PHP-файлов.
- Нативная compile-only трасса `corpus/compile_only_dumps/01_calls.log` подтверждает форму `SEND_VAL → DO_FCALL` на собственном PHP 5.2-коде; соответствие каждого сырого ключа Zend Encoder нативному opcode остаётся эмпирическим.

- Поддержка нативной операции `DIV (4)` добавлена на основании сохранённого кандидата заголовков семейства PHP 5.2, без повышения статуса доверия сырого Encoder mapping. После неё `fun_all.php` имел **13 из 23** экспериментально обрабатываемых групп; после поддержки вызовов Encoder их стало **19 из 23**, после поддержки вызовов в коротких логических условиях — **20 из 23** (остались `out_price`, `uc_rus`, `out_field`). Весь файл по-прежнему `unsupported` и в метрику 9 не входит.

## Правило позиции opcode Encoder (v29)

- `src/zend_decompiler/opcode_position.py` описывает эмпирическую модель: байт опкода в сериализованном потоке хранит `native_opcode + (index mod 8)`, то есть `native_opcode = base[байт] − (index mod 8)`. Таблица `base` содержит **107** байтов и воспроизводит **313 из 313** ключей эмпирической карты без единого противоречия.
- Правило используется **только там, где у карты нет записи**, и никогда не перекрывает запись карты. При загрузке правило сверяется с картой и отказывается работать при любом расхождении.
- Предсказание принимается, только если **форма операндов** совместима с обработчиком PHP 5.2 предсказанного опкода (сигнатуры берутся из сохранённого `reference_headers_php52_candidate/zend_vm_def.h`, независимо от архивных трасс). Несовместимое предсказание отвергается.
- Следствие: ранее неразрешённый ключ `1:199` определяется как `base 99 − 1 = 98` (`ZEND_FETCH_DIM_TMP_VAR`); форма операндов (`op1` = TMP, `op2` = CONST, `result` = VAR) совместима с сигнатурой обработчика. **Native-доказательства у этого ключа по-прежнему нет** — статус `inferred`, а native-карта и её evidence не изменены.
- Независимая сверка с архивом трасс: **292** однозначных ключа совпадают, противоречий нет; у двух ключей с несколькими кандидатами предсказание входит в список кандидатов; ключ `1:199` в архиве вообще не имеет кандидата.
- Данные: `data/opcodes/encoder_opcode_base.json`, `encoder_opcode_evidence.json`, `encoder_opcode_base.json.meta.json` со своими SHA-256.
- Проверки: `tests/test_opcode_position.py` — 13 содержательных тестов (воспроизведение всей карты, сверка с архивом, запрет перекрытия записей карты, отказ при противоречии, отказ по форме операндов, отказ для неизвестного байта и для отрицательного предсказания).

## Конструкция `foreach` и переменные-переменные (v29)

- Нативная форма цикла установлена собственным compile-only probe на PHP 5.2.17: `FE_RESET`, `FE_FETCH`, `OP_DATA` (137, `ZEND_OP_DATA` из `zend_compile.h`), затем `ASSIGN` (по значению) или `ASSIGN_REF` (по ссылке), тело, `JMP`, `SWITCH_FREE`. Признак ссылки — `FE_RESET.extended = 3`.
- Сериализованный поток хранит связывание переменной цикла в одной инструкции; декодер распознаёт **конструкцию** по последовательности `FE_RESET → FE_FETCH → связывание → присваивание`, а не по номеру опкода. Восстанавливается `foreach ($arr as &$v) { … }`; элемент цикла не имеет выражения вне конструкции, поэтому его значение помечается маркером, и утечка маркера в код отвергает блок.
- `FE_FETCH` в графе управления — двухстороннее ветвление (тело / выход цикла); заголовок цикла с несколькими обратными рёбрами допускается, обход останавливается на заголовке.
- Машина состояний не умеет выразить `foreach` и **отказывает** для таких групп вместо искажённого кода.
- `FETCH_W` над скомпилированной переменной — это переменная-переменная (`$$name`), а `ASSIGN_REF` с двумя контейнерами — общее присваивание по ссылке (`$a = &$b;`). Форма `global $x;` распознаётся отдельно и сохраняется.
- Результат: `fun_all.php` восстановлен целиком (23 из 23 групп), файловая метрика выросла **9 → 10**. Остался один незакодированный вход `header_admin.php`.
- Проверки: `tests/test_foreach.py` — 10 содержательных тестов, включая отказ при `FE_FETCH` без сброса, отказ при связывании вне цикла, отказ при чужом итераторе и отказ при неподдерживаемой форме `FETCH_W`.

## Вызовы в коротких логических условиях (v29)

- `crossblock.py` теперь допускает операндом сравнения **результат вызова**: вызов декодируется как один замкнутый отрезок и встраивается в условие. Это меняет момент выполнения вызова, поэтому правила строгие: вызов обязан лежать в том же базовом блоке, что и короткое замыкание, и ни один оператор этого блока не должен выводиться **после** вызова (иначе порядок вычислений изменился бы).
- Декодер помнит, какая инструкция породила каждый выведенный оператор (`statement_sources`), и `structure.build_graph` проверяет это условие перед свёрткой.
- Результат: `out_link` в `fun_all.php` восстанавливается целиком, условие — `((strstr($REQUEST_URI, 'htm') == '') && ($old_search != 'y'))`. Число обрабатываемых групп `fun_all.php` выросло **19 → 20 из 23**.
- Проверки: `tests/test_crossblock_calls.py` — 9 тестов, включая отказ при вызове вне блока замыкания, отказ при операторе после вызова, отказ при результате вызова не в том слоте и проверку точной диагностики отказа на подделанном входе.

## Вызовы Encoder по таблице символов файла (v29)

- `src/zend_decompiler/encoder_calls.py` распознаёт на **уровне Encoder** терминатор вызова функции, объявленной в том же файле: `op1` — индекс в `header_symbols`, `extended_value` — число аргументов. Это **не** native-карта: native-номер этих позиций остаётся нерешённым, `opcode_map.json` не переписывается.
- Правила fail-closed: индекс в диапазоне → символ объявлен в этом же файле → `argc` равен числу `RECV` вызываемой → `SEND_*` идут подряд в одном базовом блоке с корректными маркерами позиций → `op2 = UNUSED(0,1)`, `result = VAR` → имя — валидный PHP-идентификатор. Любое нарушение оставляет файл в `unsupported`, а не угадывает вызов.
- Кросс-проверка на текущем корпусе: **18/18** мест вызова разрешаются в функцию, объявленную в том же файле, и **18/18** совпадают `argc` и число `RECV` вызываемой. Статус — `inferred`; независимой native-трассы того же потока нет.
- Данные лежат отдельно от native-карты: `data/opcodes/encoder_call_map.json`, `encoder_call_evidence.json` и `encoder_call_map.json.meta.json` со своими SHA-256.
- Результат: `links_fun(1).php` восстановлен целиком (`send_mail($url_mail, $id_link)`, `count_ln($id_ln_groups, 0)`), файловая метрика выросла **8 → 9**. `fun_all.php` остаётся `unsupported` по независимым причинам (TMP-слияние, `foreach`, `FETCH_W`).
- Проверки: `tests/test_encoder_calls.py` — 22 содержательных теста, включая 12 негативных случаев отказа и проверку подделанного входа, который обязан остаться `unsupported`.

## Данные и документы

- `data/opcodes/opcode_map.json` и `opcode_evidence.json` — неизменённые эмпирические данные, защищённые SHA-256. Метаданные `opcode_map.json.meta.json` содержат контрольные суммы и гипотезы; **наличие записи в карте не означает независимого подтверждения**.
- `data/opcodes/encoder_call_{map,evidence}.json` и `encoder_call_map.json.meta.json` — семантика вызовов **на уровне Encoder**, отдельная от native-карты и защищённая собственными SHA-256; статус `inferred`.
- `data/opcodes/encoder_opcode_{base,evidence}.json` и `encoder_opcode_base.json.meta.json` — правило позиции opcode, также отдельное от native-карты и со своими SHA-256; статус `inferred`.
- `data/research/{alignment,analysis,header_audits}.json` — read-only свидетельства; это не активные правила декомпиляции. История сравнения с несовместимыми современными заголовками сохранена в `header_audits.json`, а сами современные заголовки не хранятся в рабочем дереве.
- `tests/`, `golden/reference/`, `sample_inputs/` — тестовые входы и текущие эталоны. Эталоны можно обновлять вместе с изменением алгоритма, но не только ради формального прохождения тестов.
- `tests/fixtures/batch_report.json` — один архивный JSON batch для проверки схемы (его пути к прошлым отчётам — исторические, не действующие файлы).
- `research/fragments/` — 12 уникальных **частичных** PHP-кандидатов из прежних прогонов, не пригодных для запуска; сохранённые read-only тексты лежат в `research/diagnostics/`. Архив остаётся воспроизводимым: все 12 файлов побайтово совпадают с текущим выводом инструмента.
- `research/diagnostics/phpinfo.html` — предоставленный владельцем снимок `phpinfo()` с версиями окружения; техническая оценка и ограничения приведены в `PROJECT_STATUS.md`. Связанные изображения находятся рядом в `phpinfo_files/`.
- Старые копии `examples/batch_*`, `generated/`, `user_candidate_v19.php` исключены из рабочей ветки; при необходимости доступны через Git history.
- **[PROJECT_STATUS.md](docs/PROJECT_STATUS.md)** — ограничения, доказательства, нерешённые ключи `1:199` и `140`, безопасные направления развития и полный перечень JSON.
- Старые отчёты, код устаревших версий и прежние корневые скрипты доступны только в Git history.

После очистки сохранено **38 уникальных PHP-файлов**: 11 исходных образцов, 10 неизменяемых golden, 5 собственных фикстур и 12 фрагментов. Удалено 38 дублирующих результатов предыдущих выпусков (отличие только в комментарии версии или точное совпадение).

Проект исследовательский; отсутствие падений тестов и совпадение PHP-кандидатов по байтам **не доказывают** эквивалентности реальному PHP.
