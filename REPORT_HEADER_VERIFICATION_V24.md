# Zend Decompiler v24 — этап A: проверка предоставленных заголовков

## Область изменений

Это ограниченный этап проверки источников истины. Ядро декомпиляции, эмпирическая таблица опкодов и golden-набор **не изменены**.

Пользователь предоставил три файла: `zend_vm_opcodes.h`, `zend_vm_def.h`, `zend_compile.h`. Их побайтовые копии сохранены в `reference_headers_incompatible/`, чтобы результаты проверки можно было воспроизвести. **Эти заголовки нельзя использовать как справочник PHP 5.2.17.**

## Проверяемые первичные сведения из загруженных файлов

Из `zend_vm_opcodes.h`:

| Нативный номер | Определение | Строка | Упоминание `ZEND_VM_HANDLER` в `zend_vm_def.h` |
|---:|---|---:|---|
| 49 | `ZEND_CHECK_VAR` | 172 | Строка 9377 |
| 140 | `ZEND_MAKE_REF` | 262 | Строка 9390 |
| 199 | `ZEND_CHECK_UNDEF_ARGS` | 321 | В точном шаблоне `ZEND_VM_HANDLER` не найдено |

Внешнее контрольное свидетельство: опубликованный архив Debian для PHP 5.2.0 называет opcode 140 `ZEND_DECLARE_INHERITED_CLASS`, не `ZEND_MAKE_REF`: https://sources.debian.org/src/php5/5.2.0%2Bdfsg-8%2Betch16/Zend/zend_vm_opcodes.h . Это **не** точная сборка 5.2.17 и не достаточное основание подтверждать любую эмпирическую запись таблицы.

Официальный архив исходников PHP 5.2.17: https://museum.php.net/php5/ (пакет `php-5.2.17.tar.bz2`). В этой среде скачать его не удалось, поэтому точного независимого сравнения с 5.2.17 **не было**.

Отдельное предостережение: эмпирический ключ `1:199` — ключ сериализации (`позиция:байт`), а **не нативный opcode 199**. Совпадение числа 199 с нумерацией современного заголовка не имеет доказательной силы. Никаких переназначений ключа `1:199`, opcode 140 или предполагаемого opcode 49 не выполнено.

## Реализация

- `zend_header_audit.py`: автономный read-only анализатор трёх заголовков, SHA-256, номера строк, нативные определения и обработчики; выдаёт `incompatible_with_php_5_2`, `incomplete_headers` или `unverified_version`. Положительный вывод о точной версии **не предусмотрен без внешней аттестации**. Никаких изменений таблицы декомпилятора.
- `header_verification_v24.json`: машинный отчёт.
- `tests/test_header_audit_v24.py`: четыре теста отклонения неподходящих заголовков, отсутствующих и фиктивных заголовков, а также неизменности хеша эмпирической таблицы.

## Воспроизведение

```bash
cd zend_decompiler_v24
python zend_header_audit.py reference_headers_incompatible -o header_verification_v24.json
python -m unittest discover -s tests -v
python zend_cli.py batch sample_inputs -o /tmp/v24_sample_output \
  --php-linter "$PWD/php52_linter" \
  --lib-dir /mnt/data/php52_libs --isolate-parser
```

Получено при проверке:

- 32/32 теста — `OK` (ранее 28/28).
- Пакетный прогон — `total=11, generated=8, unsupported=2, not_encoded=1`.
- Таблица `opcode_map_observed_v20.json` неизменна (хеш из `.meta.json`).
- Счётчики `confirmed/inferred/unknown` сохраняются `0/305/9`.
- Round-trip `not_run`; семантическая эквивалентность не доказана.

Пакетная проверка PHP выполнялась только в режиме `-n -l`. Входные PHP-файлы как программы **не исполнялись**.

## Следующий входной материал

Нужны исходники **именно PHP 5.2.17** для `Zend/zend_vm_opcodes.h`, `Zend/zend_vm_def.h`, `Zend/zend_compile.h` (предпочтительно с происхождением и SHA-256 всего дистрибутива) и, для подтверждения кодированных соответствий, пары собственных исходников и их кодированных версий от того же Zend Encoder. Даже точные 5.2.17 заголовки подтверждают *нативную* нумерацию, но сами по себе не доказывают сопоставление с сериализованными ключами кодировщика.
