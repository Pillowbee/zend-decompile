# Консолидация Zend Decompiler v28 — 22 октября 2026

## Решение

В рабочей копии оставлена одна основная реализация восстановления PHP и единый
публичный движок `zend_engine.restore_result()`. Старые версии скриптов удалены
либо (для реально используемой логики) переименованы в непересекающиеся
канонические модули. Все тесты импортируют только актуальный код.
Исходные исследовательские образцы, таблицы opcode и golden-эталоны сохранены.

### Удалены исторические скрипты (8)

- `legacy/zend_restore_v18.py` — отдельный исследовательский восстановитель.
- `zend_restore_v19.py` — совместимая CLI-обёртка старого выпуска.
- `zend_restore_v20.py` — старая CLI-обёртка, использовавшая то же ядро.
- `zend_batch_v20.py` — заменён действующим `zend_batch.py`.
- `validation_v19.py`, `validation_v20.py`, `validation_v23.py` — заменены
  версионно-независимыми тестами и командой `zend_cli.py validate`.
- `zend_prefix_restore_v11.py` — удалён после сравнения с новейшим
  `zend_prefix_restore.py` на 11 образцах (см. доказательство ниже).

Исторический API `restore_v20_compat()` удалён из `zend_restore_core.py`:
текущие тесты сверяют основной движок напрямую с неизменёнными golden-данными.

Добавлен `zend_assets.py`: единое разрешение путей к текущей таблице,

Обновлены активные импорты, `pyproject.toml`, CLI и README.
Команды отдельных диагностических модулей получили актуальную карту opcode
по умолчанию. У `zend_calibrate.py` требуется явный `--old-map`, чтобы

### Тесты теперь не привязаны к имени предыдущего выпуска

- 11 версионных имён `tests/test_*_vNN.py` переименованы в смысловые.
- Тесты не импортируют устаревшие `zend_restore_vNN` и не хранят в собственном
  коде имена активной карты opcode, golden-директории или файлов схем с
  номером версии; разрешение исторических файлов централизовано в `zend_assets.py`.
- Эталоны перенесены `golden/v20/` → `golden/reference/` **без изменения байтов**.
- Актуальные схемы получили имена `audit.schema.json`, `batch_report.schema.json`,
  `opcode_metadata.schema.json`; старые варианты схем перенесены в `schemas/legacy/`.
- Проверка golden-серии использует текущий `zend_engine.restore_result()`:
  код сверяется побайтово после нейтрализации **только комментария версии**,
  а все прежние поля отчётов каждого восстановленного блока сравниваются
  с историческими golden-аудитами.
- Проверка архитектуры запрещает исходники с `_vNN.py` и устаревшие
  импорты реставраторов.
- Проверка превью сравнивает SHA-256 каждого ранее успешного блока, включая
  инструкции и ветвления, с оригиналом из Git-состояния `5e03d01`, а также
  требует не меньшего количества успешно восстановленных блоков и инструкций.
  Сохранён независимый baseline `tests/fixtures/preview_completed_blocks.json`.

## Неизменённые исторические данные

Версионные метки **в файлах данных**, например
`opcode_map_observed_v20.json`, `opcode_evidence_v21.json`, старых журналах,
генерированных отчётах и сохранённых исследовательских артефактах, оставлены:
это атрибуция источника и контроль SHA-256, а не рабочие версии декомпилятора.

Не изменялись оригинальные PHP-образцы, словарь и файлы opcode-данных.
Восстановленные `.php` **никогда не исполнялись**. Синтаксический PHP 5.2
линтер в рамках этой консолидации не запускался, если не считать прежних
сохранённых свидетельств; семантическая эквивалентность не доказана.

## Ограничения

Не решены ранее неизвестные `1:199` для `fun_all.php` и семантика opcode 140
для `links_fun(1).php`. Новые локально восстановленные блоки являются
**диагностическим прогрессом**, а не доказательством корректности конечного
PHP. Отсутствие внешних трасс и PHP 5.2 native oracle ограничивает
доказательство эквивалентности. Историю удалённых скриптов сохраняет Git;
в новом архиве код старых версий отсутствует.
