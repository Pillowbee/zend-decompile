# Zend Decompiler v27 — проверяемое продолжение v26

## Основание, границы и метод

Начальная точка — исходники и тесты v26. До изменения кода выполнен базовый прогон:
`python -m unittest discover -s tests -q`: **49 тестов, 0 ошибок, 2 пропуска**.
Данные golden, исходные sample streams и таблица Encoder оставлены неизменными.

Цель v27 — устранить найденную *контрольную* ошибку в CFG, ограничить область
применения CFG при неизвестных переходах и предоставить воспроизводимые
синтаксические свидетельства неоднозначностей. **Новые encoder opcode не выведены.**
Ни предоставленный закодированный PHP, ни восстановленные PHP-кандидаты не
исполнялись. Никакой ZendOptimizer.so или PHP 5.2 executable не загружался.

## 1. Новая подтверждённая ошибка: `EXIT` ошибочно продолжал CFG

В v26 `zend_cfg_v11.py` распознавал как терминальные лишь `RETURN=62` и
`HANDLE_EXCEPTION=149`. Native `ZEND_EXIT=79` ошибочно попадал в правило
`fallthrough`. В поставленном пользователем `zend_vm_def.h` обработчик 79
вызывает `zend_bailout()`, и обычное продолжение не является допустимым
следующим CFG-ребром. Это **доказательство семантики native ID**, а не
подтверждение соответствия произвольному encoded key.

Синтетический воспроизводимый вход: `#0 EXIT; #1 BOOL result=TMP(0); #2 ECHO TMP(0); #3 RETURN`.

- v26: один условно достижимый блок `B000` с `ECHO #2`; ложное
  `reaching_definition_indices=[1]`.
- v27: `#0` завершает блок; `#1..#3` недостижимы; **0** достижимых TMP-чтений.

Проверка: `test_exit_has_no_fallthrough_reaching_definition`.

## 2. Fail-closed для некорректно смоделированных переходов

В `zend_cfg_v11.py` запрещён CFG для native opcode гипотез
`50 BRK`, `51 CONT`, `77 FE_RESET`, `78 FE_FETCH`, `107 CATCH`, `108 THROW`.
Исторический `zend_vm_def.h` содержит `ZEND_VM_JMP`/`ZEND_VM_SET_OPCODE`
или исключительный поток, не представленный прежним правилом `fallthrough`.
Запрет **консервативен**: мы не пытаемся угадать адреса, исключительные рёбра,
операнды и вставки оптимизатора.

`zend_readonly_dataflow.py` преобразует эти случаи и неверные адреса переходов
в структурированный ответ `unsupported`, не создавая PHP. Для `EXIT=79`
предусмотрена подтверждаемая статическая терминальная семантика.

В исходных данных целевых файлов данный guard не изменил количество
`analyzed_syntactically`: `fun_all.php` **15/23**, `links_fun(1).php` **4/6**,
поскольку существенные `FE_FETCH` уже находятся в группах, заблокированных
неизвестным ключом `1:199`. Это не доказывает полную корректность остальных CFG.

## 3. Свидетельства путей для межблочных TMP

В `zend_readonly_dataflow.py` для неоднозначных синтаксических TMP/VAR-чтений
добавлен ограниченный BFS по состояниям `(instruction_PC, last_definition)`.
Каждый найденный путь снабжается номером определения и последовательностью
инструкций/блоков. Зацикливание ограничено множеством состояний и `state_budget`;
превышение бюджета явно отмечается, а не трактуется как доказанная невозможность.

Для `fun_all.php` / `out_link` / чтение `#16`, `TMP[2,0,0]` получены два пути:

- определение `#13`: `0..13 -> 16`;
- определение `#15`: `0..13 -> 14 -> 15 -> 16`.

Это *свидетельства структурной достижимости*, не доказательство выполнимости
веток при реальных значениях данных и не разрешение семантики `JMPZ_EX/BOOL`.
Выбирать один из producer в эмиттере по-прежнему нельзя.

Первоначальная гипотеза о пропуске `undefined` при слиянии веток **не подтвердилась**:
контрпример возвращает `[-1,1]` уже в v26. В v27 добавлен тест, но исправлять
несуществующую ошибку не требовалось.

## 4. Независимая модельная проверка

Добавлен bounded model check: **300** детерминированных синтетических CFG
длиной пять инструкций (переходы, циклы, определение, чтение, RETURN, EXIT).
Результаты блочного fixed-point dataflow независимо сверяются с прямым BFS
конечных состояний `(instruction_PC, last_definition)`, без использования
функций `cfg_for_group` в эталонном проверяющем алгоритме.

В проверенном ограниченном пространстве получено **300/300 совпадений**.
Это не доказательство корректности для произвольных графов или семантики Zend Encoder.
Тест: `test_reaching_definitions_against_independent_instruction_graph`.

## 5. Literal-free triage для нерешённых файлов

Команда:

```bash
python zend_triage_v27.py sample_inputs/fun_all.php 'sample_inputs/links_fun(1).php' -o TRIAGE_V27.json
```

`TRIAGE_V27.json` содержит SHA-256 входов, ключи, статусы evidence,
типы операндов, локальное окно инструкций вокруг неподтверждённых ключей,
а также неоднозначные TMP/VAR-чтения и их структурные пути. **Литералы PHP,
исходный код и исполняемый PHP в отчёт не записываются.**

| Файл | Групп | Синтаксически проанализировано | Отказов | Событий triage |
|---|---:|---:|---:|---:|
| `fun_all.php` | 23 | 15 | 8 | 22 |
| `links_fun(1).php` | 6 | 4 | 2 | 2 |

Для `fun_all.php` из 22 событий: 18 неподтверждённых encoded
key в контексте вызовов/foreach, 4 неоднозначных TMP-чтения. Включены оба
контекста `1:199`: `out_price #65`, `uc_rus #17`.
Для `links_fun(1).php`: спорный `6:226` в `<main> #14` и `3:160` в `count_ln #3`.

Таблица opcode, `opcode_evidence_v21.json`, golden-файлы и dictionary не
изменены. Исторические несоответствия `3:139` и `6:236` остаются
**не подтверждёнными первичными трассами**. `SEND_VAR` / `SEND_VAL`
не исправлялись предположением.

## 6. Проверки после изменений

- `python -m unittest discover -s tests -q`: **57 тестов, 0 ошибок, 2 пропуска**.
  Это 49 исходных тестов v26 + 8 новых методов; один из новых методов содержит
  300 автоматически сгенерированных проверок.
- `python zend_cli.py batch sample_inputs -o /tmp/v27_batch --isolate-parser`:
  код выхода **2 (ожидаемо)**, **8 generated / 2 unsupported / 1 not_encoded**.
  Для обоих unsupported отсутствуют выходные исполняемые `.php`.
- SHA-256 `golden/v20/manifest.json`: **16/16** code/audit артефактов;
  **11/11** исходных input; словарь и таблица соответствуют манифесту.
- Round-trip, semantic equivalence, выполнение PHP, проверка php -l,
  независимый Encoder-oracle: **не выполнялись**.

Два пропуска остались от v26 (необязательные исторические трассы и
отсутствующий диагностический PHP 5.2 probe).

## 7. Что блокирует фактический ресторинг

**`fun_all.php`:** недоказанная семантика нескольких веток, `TMP[2,0,0]`
в `out_link`, ключ `1:199` после `FE_FETCH` в двух функциях и случаи 140,
о которых известно лишь наблюдательное сопоставление. Нужно подтвердить
на реальных выровненных serialized и native op_array-записях, либо оставить
группы `unsupported`. Исторические логи в архив не входят.

**`links_fun(1).php`:** `SEND_VAR` без однозначно восстановленного состояния
вызова в `<main> #12` и сомнительный 140 при encoded `6:226` в `#14`;
не разрешать это эвристической заменой opcodes.

Следующий безопасный шаг — получить **собственные** пары исходник PHP 5.2 →
*подтверждённый* SSG Team serialized output + независимые native compile-only
трассы из той же версии компилятора. Компиляция только собственных фикстур;
предоставленные encoded PHP не исполнять. Без этих данных нельзя научно
добросовестно заявлять восстановление обоих проблемных файлов.
