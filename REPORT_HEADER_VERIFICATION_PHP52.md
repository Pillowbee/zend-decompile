# Дополнение к v24: повторная проверка заголовков семейства PHP 5.2

## Исходные данные и ограничения

Повторно загружены три заголовка `zend_vm_opcodes.h`, `zend_vm_def.h`, `zend_compile.h` (побайтовые копии: `reference_headers_php52_candidate/`). Хеши и точные строки: `header_verification_php52_candidate.json`. Данные *не* включаются в активную таблицу Zend Encoder. Отсутствует независимая аттестация происхождения именно от тарбола PHP 5.2.17, так что установлена совместимость **макета нативных опкодов семейства PHP 5.2**, но не тождество исходникам конкретного релиза.

Старые загруженные заголовки (в `reference_headers_incompatible/`) относятся к современному Zend Engine и остаются непригодными для PHP 5.2.

## Подтверждено по предоставленным заголовкам

| Opcode | `zend_vm_opcodes.h` | `zend_vm_def.h` | Статус |
| ---: | --- | --- | --- |
| 49 | строка 70, `ZEND_SWITCH_FREE` | строка 2556, `ZEND_VM_HANDLER(49, ZEND_SWITCH_FREE,...)` | Два согласованных определения нативного номера |
| 140 | строка 141, `ZEND_DECLARE_INHERITED_CLASS` | строка 3776, `ZEND_VM_HANDLER(140, ZEND_DECLARE_INHERITED_CLASS,...)` | Два согласованных определения нативного номера |
| 199 | отсутствует | отсутствует | Не определён в предоставленном наборе |

Всего извлечено **129 числовых определений**. Среди соответствующих этим номерам найденных обработчиков VM расхождений нет. В частности, `ZEND_FE_RESET=77`, `ZEND_FE_FETCH=78`, `ZEND_CATCH=107`, `ZEND_THROW=108`, `ZEND_BRK=50`, `ZEND_CONT=51` согласуются между файлами. Независимое опубликованное определение PHP 5.2.0: https://sources.debian.org/src/php5/5.2.0%2Bdfsg-8%2Betch16/Zend/zend_vm_opcodes.h ; оно подтверждает *семейство нумерации*, не побайтовую идентичность 5.2.17.

**Важно:** `1:199` — это ключ сериализатора (позиция/байт), не нативный номер opcode 199. Использовать отсутствие нативного 199 для декодирования `1:199` нельзя. Аналогично наличие нативного 140 не доказывает, что эмпирическая запись кодировщика с числом 140 представляет `DECLARE_INHERITED_CLASS`. Никакой статус `inferred` -> `confirmed` не изменён.

## Исправление анализатора

`zend_header_audit.py` ранее терял все определения из исторического заголовка, если не находил `ZEND_VM_LAST_OPCODE`. В старом формате таблица заканчивается EOF. Теперь разбор поддерживает оба варианта. Для совместимого макета выдаётся `php_5_2_family_layout_unverified_build`, **не** `verified_php_5_2_17`, и `suitable_for_encoder_opcode_confirmation=false`. Дополнительно сверяются названия обработчиков VM и фиксируются все расхождения. Признаки современного Zend Engine по-прежнему приводят к отказу.

## Воспроизводимые проверки

```bash
cd zend_decompiler_v24
python zend_header_audit.py reference_headers_php52_candidate -o header_verification_php52_candidate.json
python zend_header_audit.py reference_headers_incompatible -o /tmp/modern.json
python -m unittest discover -s tests -v
python zend_cli.py batch sample_inputs -o /tmp/v24_header_check \
  --isolate-parser --php-linter "$PWD/php52_linter" --lib-dir /mnt/data/php52_libs
```

На проверенной среде: **36/36 тестов**, прежние golden-тесты проходят. Пакетная проверка: **11 входов, 8 полных PHP-кандидатов, 2 отказа, 1 открытый PHP**; для восьми кандидатов в отчёте `syntax_checked=true`, т.е. использован только `php -n -l`. Отсутствия регрессий достаточно для этого read-only изменения, но это **не** проверка эквивалентности поведения.

Проверка исходников точной сборки PHP 5.2.17, сериализованных ключей `1:199` и странного контекста `140`, а также round-trip по опкодам остаются **не выполненными**. Для этих задач нужны удостоверенный тарбол исходников и проверенный механизм выравнивания нативных и сериализованных инструкций.
