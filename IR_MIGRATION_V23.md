# План миграции на типизированный IR (оценка кода v23)

## Почему сейчас нельзя делать полный переход

- `zend_serial_parser.py:Reader.node()` выдаёт словари с типами 1/2/4/8/16 и числовыми полями; функция `parse_binary()` требует заголовок `SSG Team`, а не нативный op_array.
- `zend_prefix_restore_v17.py:Decoder.defs` содержит `bytes` либо `list[bytes]`; `val()` использует текстовые выражения, `run()` строит `Segment.statements: list[bytes]`. Форматирование, временные значения и побочные эффекты слиты в одну структуру.
- `zend_crossblock_v17.py:join_proofs()` передаёт отдельные доказанные `expression_hex`; общего слияния reaching definitions/phi нет.
- `zend_structure_v17.py:Emitter` и `zend_state_v19.py:state_emit` оперируют уже текстовыми строками PHP; `while/switch` остаётся fallback.
- Корпус компилятора существует, но не адаптирован к сериализованному представлению Encoder; проверенный round-trip **отсутствует**. Нельзя безопасно принять изменения, которые сдвигают семантику и сохраняют лишь синтаксис.

## Консервативная последовательность

1. **Read-only Operand IR**: `Const(raw bytes)`, `CV(id, raw_name)`, `Tmp(kind,slot0,slot1)`, `Unused(word0,word1)`, `SourceSpan(function,index,line)`; проверка соответствия существующим словарям без изменений output.
2. **Expr / Stmt как отдельный слой** с переходным `render_legacy_bytes()`. Вначале только `BOOL_NOT`, бинарная арифметика и литералы; golden обязателен после каждого обработчика.
3. **Верифицируемый reaching-defs** для временных значений между блоками: разрешать лишь уникальное определение, доминирующее все использования, и доказанную отсутствие побочных эффектов; иначе `unsupported`. Не заменять undefined TMP пустым литералом.
4. **FE_RESET/FE_FETCH**: сначала собственные циклы `foreach($xs as $v)`, позже ключи и ссылки. Нужна явная проверка `SWITCH_FREE` и необъяснённого `1:199` на совпадающем закодированном потоке; без неё не включать правило.
5. **list(), isset/empty, try/catch**: по одному семейству опкодов и верификации operand flags, отдельные corpus/golden тесты и PHP 5.2 `-n -l`.
6. **Structured CFG**: dominator/postdominator, распознавание природных циклов, `if/else`, `switch`, `break/continue`, краткие логические операторы, тернарный оператор. Старая state machine остаётся только безопасным резервом.

## Условия приёмки будущего шага

- Round-trip на корпусе из **собственных** PHP 5.2 программ: `source -> native dump -> adapter -> restored -> native dump`, со сверкой потоков opcode и нормализацией CV/TMP.
- Изменения в golden после согласованной миграции сохраняются отдельным новым эталоном; существующий `golden/v20` не переписывается.
- Каждый новый семантический handler снабжён тестом на корректную и отрицательную ветку, точной причиной отказа, синтаксической проверкой PHP 5.2, без исполнения сгенерированного PHP.

## Решение итерации v23

Ядро реконструкции **не расширять**, пока инструмент не умеет принимать собственный native op_array без неподтверждённых преобразований. В v23 изменена наблюдаемость правил декодера и контекст отказа; 8 полных кандидатов остались теми же по байтам за исключением заголовка версии.
