# Независимый аудит и ограниченный рефакторинг Zend Decompiler v28

Дата: 2026-10-21. Объект проверки: исходный архив `zend_decompiler_v28.zip`.
Данный отчёт фиксирует **фактически выполненные** изменения и ограничения.
Исторические утверждения `REPORT_V*.md` не принимались как доказательства:
сверялись исходный код, зависимости, файлы, тесты и результаты реальных прогонов.

## 1. Предварительная фиксация и инвентаризация

В отдельной рабочей копии зафиксирован неизменённый baseline Git-коммит.
После этого составлена карта статических Python-импортов и точек входа,
проверены `pyproject.toml`, `.github/workflows/test.yml`, API, тесты,
SHA-256 данных, побайтовые дубликаты и поведение 11 встроенных входов.
Известная граница статического анализа: сторонние потребители отдельных
исторических CLI/модулей неизвестны; отсутствие импорта **не доказательство**
неиспользуемости. По статическим импортам после изменений: **29 модулей в корне,
63 направленные связи, циклов нет**. Отдельно проверялось наличие динамического
Python-import по явным шаблонам; гарантий для внешних клиентов это не даёт.

## 2. Baseline до редактирования

- `python -m unittest discover -s tests -v` — **70 тестов, 0 failures,
  0 errors, 3 skips**.
- `python zend_cli.py batch sample_inputs -o <новый каталог> --isolate-parser`
  — exit **2** (ожидаемо), **8 candidate_generated / 2 unsupported /
  1 not_encoded**.
- `python zend_cli.py dataflow sample_inputs/fun_all.php -o <новый файл>`
  — 23 группы, без генерации PHP.
- `python zend_cli.py --version` выдавал `26.0.0-experimental`, тогда как
  `pyproject.toml` требовал `28.0.0`.
- Два `zend_crossblock_*.py` реализовывали одинаковые 131-строчные
  алгоритмы; импортировали разные декодеры (`v11` и `v17`).

**Пропущенные тесты:** исторические диагностические трассы отсутствуют в
архиве; локальный PHP 5.2 compile-only probe отсутствует; две необязательные
открытые редакции пользовательского кода отсутствуют. Ничего из этого не
заполнялось предполагаемыми данными.

## 3. Эксперимент перед объединением

Для каждого из 11 файлов были сохранены *точные JSON-результаты*
`zend_block_previews_v12.run()` (включая отказ для `header_admin.php`).

1. Подмена **только** алгоритма на `zend_crossblock_v17.analyzed_source`
   при сохранении `Decoder` из `zend_prefix_restore_v11.py` дала
   **11/11 совпадающих результатов**.
2. Подмена ещё и `Decoder` на v17 изменила результаты **4 из 11**:
   `fun_all.php`, `gr_wares1.php`, `import(1).php`, `user.php`.
   Некоторые блоки перестали быть помечены как `unsupported`.
   Такое расширение нельзя считать подтверждённой декомпиляцией.
3. Решение: удалить дубликат `zend_crossblock_v12.py`, оставив
   старую локально консервативную семантику preview. Не вводить
   адаптеры и wrappers ради старого имени.

Для защиты от будущего незаметного изменения добавлен
`tests/test_refactor_regression.py`: хеши нормализованного диагностического
JSON для всех 11 образцов, а также проверка совпадения `__version__`
с `pyproject.toml`. SHA-хеши зафиксированы **до** изменения кода.

## 4. Конкретные изменения

- **DELETE:** `zend_crossblock_v12.py` (131 строк); `examples/import_candidate_v20.php`
  и `examples/gr_wares1_candidate_v20.php` (дубликаты без внутренней ссылки).
- **MERGE:** `zend_block_previews_v12.py` теперь использует
  `zend_crossblock_v17.analyzed_source`, а `Decoder` оставляет v11.
- **REFACTOR:** `zend_engine.__version__` теперь `28.0.0`; метка
  восстановления `v28` вместо `v26`. Это меняет лишь заголовок
  кандидатного PHP и поля версии в JSON-аудитах.
- **REFACTOR:** повторный импорт двух функций ядра в `zend_research_v19.py`
  объединён в один импорт. Алгоритм исследования не менялся.
- **PACKAGING:** удалено имя выбывшего модуля из `pyproject.toml`;
  `networkx>=2.8` оставлен, поскольку реально необходим.
- **DOCS:** `README.md` заменён текущей инструкцией с картой зависимостей
  и ограничениями. Старые отчёты сохранены в исходном виде.
- **TESTS:** добавлен регрессионный файл и `.gitignore` для кэшей сборки.
- **Не сделано:** массовое переименование модулей `vNN`, отключение fallback,
  замена подсистем, удаление исторических CLI, изменение opcode-таблиц,
  «улучшение» golden-файлов, написание новых PHP-генераторов.

## 7. Оставшиеся проблемы и риск-реестр

| Приоритет | Статус | Проблема / граница |
|---|---|---|
| Высокий | **INVESTIGATE** | Эмпирическая opcode-таблица не доказана полным независимым Encoder/Loader oracle; ключ `1:199` не назначен. |
| Высокий | **INVESTIGATE** | `fun_all.php`: TMP на `out_link #16` и неопознанные инструкции `out_price #65` / `uc_rus #17`; 12/23 групп исследовательски восстанавливаются, **полный PHP не генерировать**. |
| Высокий | **INVESTIGATE** | `links_fun(1).php`: `SEND_VAR` без доказанного call-context на #12, спорный ключ opcode 140 на #14; 4/6 групп частичные, **полный PHP не генерировать**. |
| Высокий | **KEEP ограничение** | Golden фиксирует байты кодогенерации, **не** эквивалентность реальному PHP на входах/побочных эффектах. |
| Средний | **INVESTIGATE** | `zend_prefix_restore_v11.py` и v17 имеют разную семантику preview; требуются локальные soundness-assertions для всех новых ветвей перед объединением. |
| Средний | **INVESTIGATE** | Внешние вызовы исторических `validation_v*.py` и `zend_batch_v20.py` неизвестны; удаление может сломать научную воспроизводимость. |
| Средний | **KEEP ограничение** | Linux `--isolate-parser` защищает первичный парсер, а не весь процесс/неизвестные внешние PHP-инструменты. |
| Средний | **INVESTIGATE** | Compiler-oracle существует лишь для **собственных** исходников, а проверенная цепочка `native op_array` → формат защищённого serialized stream отсутствует. |
| Низкий | **KEEP** | Снимки `examples/`, `generated/` и исторические отчёты занимают место, но содержащаяся provenance-информация не доказана избыточной. |

**Главный итог:** контрольные проверки воспроизведены, единственный
доказанный дублирующийся алгоритм объединён, версии исправлены,
защита от регрессий расширена. Функциональность по восстановлению PHP **не
расширялась**, а проблема двух оставшихся файлов **не решена**.
